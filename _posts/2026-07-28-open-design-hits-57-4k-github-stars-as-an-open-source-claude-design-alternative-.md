A community project called Open Design has reached over 57,000 GitHub stars as a local-first alternative to proprietary design tools like Claude Design.

The project provides a way to generate design artifacts, such as decks, prototypes, and dashboards, without being locked into a specific cloud provider. It runs via a local daemon that detects available coding agents on your machine. It includes a library of over 250 skills and 142 design systems stored as Markdown files. This setup allows teams to swap between different AI models—including Anthropic, Google, and local options via Ollama—without having to rewrite their core workflows or design systems.

For those of us looking at the public sector, this is a relevant development for data sovereignty. Many government entities cannot use cloud-only tools because of strict security and residency rules. Open Design addresses these concerns by keeping design artifacts on the local machine rather than in a third-party cloud. It also moves prompt engineering from hidden documents into version-controlled folders. This makes it easier for teams to audit, share, and maintain standardized AI workflows while remaining compliant with security requirements. It offers a constructive path toward model agnosticism.

Is moving toward local-first, model-agnostic tools a necessary step for safe public sector AI adoption?
